# PDF → JSON без LLM

Локальный Python-парсер технической анкеты. PyMuPDF читает PDF и рисует
страницы, Tesseract распознаёт изображения, OpenCV определяет отметки в чекбоксах.
При разборе нет сетевых запросов, API или LLM. Модели Tesseract — обычный OCR.

## Установка

Нужны Python 3.10+ и установленная команда `tesseract`.
В этой среде проверено с Python 3.14.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python download_ocr_models.py
```

Последняя команда один раз скачивает официальные модели `rus` и `eng` в
`.tessdata/`. Можно вместо этого установить языковые пакеты Tesseract через
пакетный менеджер и передать их каталог через `--tessdata`.
Документация: <https://tesseract-ocr.github.io/tessdoc/Installation.html>.

## Запуск

```bash
.venv/bin/python parse_pdf.py \
  'путь/к/анкете.pdf' \
  -o parsed.python.json
```

Без `-o` результат записывается рядом с PDF с расширением `.python.json`.
Исходный файл не меняется. Шаблон определяется автоматически по заголовку и числу
страниц. Поддерживаются облачный бланк на 3 страницы и On-prem на 4 страницы.
Параметр `--no-page-text` отключает добавление полного текста страниц, сохраняя
чтение всех значений. `--template` позволяет явно указать файл шаблона.

## Структура и чтение

- `sections[].fields[]` содержит вопросы, варианты и значения.
- `value` у текстового поля — строка или `null`, если оно пустое.
- `value` у чекбоксов — массив отмеченных вариантов или `null`, если отметок нет.
  Отсутствие отметки не означает ответ «Нет».
- `reading` содержит способ чтения, координаты и долю тёмных пикселей чекбокса.
- `extraction.template` содержит имя выбранного шаблона.
- `extraction.page_text` содержит текстовый слой страницы или OCR, если слой
  скудный либо содержит повреждённые символы.
- `extraction.review` содержит ошибки и неоднозначные поля. При ошибке чекбокса
  значение всего вопроса — `null`, даже если часть вариантов прочитана.

Код завершения: `0` — нет диагностированных ошибок; `1` — ошибка запуска/формата;
`2` — JSON записан, но есть поля для проверки. Код `0` не гарантирует отсутствие
ошибок OCR.

## Шаблон и ограничения

Каждый шаблон задаёт названия вопросов, варианты ответов и области
чтения в координатах страницы 1548 × 2200. В шаблоне **нет заполненных ответов**:
они заново извлекаются из входного PDF. Названия вопросов берутся из шаблона,
а не восстанавливаются автоматически из OCR. Поэтому структурированные подписи
чище полного OCR-текста, в котором возможны ошибки.

Шаблоны рассчитаны на два поддерживаемых бланка и их заполненные экземпляры
с тем же расположением полей. Другой документ не выбирается только по числу
страниц: должен совпасть и заголовок. Для нового макета нужен новый шаблон.
Масштаб страницы нормализуется, но поворот,
смещение от сканирования, изменение макета и другая анкета требуют адаптации.
Проверки количества страниц, пропорций и рамок чекбоксов обнаруживают часть
несоответствий; это не универсальное распознавание произвольных форм.

Отметки определяются по рамке и доле тёмных пикселей внутри неё. Слабые или
нестандартные отметки могут потребовать проверки. OCR рассчитан прежде всего
на печатный текст; рукопись надёжно не поддерживается.

В облачном бланке читаются 30 полей, в On-prem — 42. Результаты разбора
записываются локально; примеры заполненных анкет не нужны для работы скрипта.

## Проверки

```bash
.venv/bin/python -m unittest -v
```

Проверяются пустой чекбокс, точка, крестик, слабая отметка, отсутствие рамки,
очистка подчёркиваний и обнаружение повреждённого текстового слоя. Сгенерированные
PDF проверяют автоматический выбор и разбор обоих макетов, OCR заголовка и отказ
для неизвестной анкеты. Эти тесты не требуют исходных заполненных документов.

Если доступны исходные PDF и эталонный JSON, дополнительные проверки сверяют
30 полей, заменяют отметку LDAP на LDAPS и проверяют неверное число страниц.
